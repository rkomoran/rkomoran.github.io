Getting Started with the CCNA: Networking Fundamentals

Why I'm Studying for the CCNA

After competing at CyberSci Regionals and spending more time in the security space, I kept running into the same wall: my networking fundamentals were shaky. I could hack around in CTF challenges, but the moment a question touched on routing protocols, subnetting, or how a packet actually traverses a network, I was guessing. The CCNA (Cisco Certified Network Associate) is the logical fix — it forces you to actually understand how networks are built, not just how to exploit them.

Week 1 is about laying the foundation. These are my notes — dense enough to be useful, not so exhaustive that I'll never re-read them.

The OSI Model

The OSI (Open Systems Interconnection) model is a conceptual framework that describes how data travels from one application on one machine to another application on a different machine. It has 7 layers, each with a distinct responsibility. Memorize them. You'll need them.

# Layer What it does Key protocols / devices
7ApplicationEnd-user interface; provides network services to appsHTTP, HTTPS, DNS, FTP, SMTP
6PresentationData formatting, encryption, compressionTLS/SSL, JPEG, ASCII
5SessionEstablishes, manages, and terminates sessionsNetBIOS, RPC, NFS
4TransportEnd-to-end delivery, flow control, error recoveryTCP, UDP
3NetworkLogical addressing and routing between networksIP, ICMP, routers
2Data LinkNode-to-node delivery, MAC addressing, framingEthernet, Wi-Fi, switches
1PhysicalRaw bit transmission over a physical mediumCables, NICs, hubs

Mnemonic

Top-down: All People Seem To Need Data Processing. Bottom-up: Please Do Not Throw Sausage Pizza Away. Use whichever sticks.

Exam tip: When a question asks which layer does X, map it precisely. "Segmentation" is Layer 4 (Transport). "Logical addressing" is Layer 3 (Network). "Framing" is Layer 2 (Data Link). Don't conflate them.

TCP/IP Model vs OSI

In practice, the TCP/IP model (which the real internet uses) collapses the 7 OSI layers into 4: Application (covers OSI 5–7), Transport (OSI 4), Internet (OSI 3), and Network Access (OSI 1–2). The CCNA tests on both, so understand how they map.

IP Addressing Basics

An IPv4 address is a 32-bit number written in dotted-decimal notation — four octets separated by dots, each 0–255. Example: 192.168.1.100.

Address Classes

Before CIDR (classless inter-domain routing) took over, addresses were divided into classes. You still need to know these for the exam:

Note: 127.x.x.x is reserved for loopback (localhost). Pinging 127.0.0.1 tests your own TCP/IP stack.

Private Address Ranges (RFC 1918)

These ranges are not routable on the public internet. NAT (Network Address Translation) maps them to a public IP at the router.

  • 10.0.0.0/8 — Class A private (10.0.0.0 – 10.255.255.255)
  • 172.16.0.0/12 — Class B private (172.16.0.0 – 172.31.255.255)
  • 192.168.0.0/16 — Class C private (192.168.0.0 – 192.168.255.255)

Your home router assigns addresses from 192.168.x.x. That's RFC 1918 in action.

Subnetting: The Part Everyone Dreads

Subnetting is dividing a network into smaller sub-networks. It sounds scary but it's just binary math — once the pattern clicks, it becomes mechanical.

CIDR Notation

CIDR (Classless Inter-Domain Routing) notation appends a slash and a prefix length to an IP address. The prefix length tells you how many bits are the network portion of the address. The remaining bits are the host portion.

  • /24 = 24 network bits, 8 host bits → 256 addresses, 254 usable
  • /25 = 25 network bits, 7 host bits → 128 addresses, 126 usable
  • /26 = 26 network bits, 6 host bits → 64 addresses, 62 usable
  • /30 = 30 network bits, 2 host bits → 4 addresses, 2 usable (point-to-point links)

Why subtract 2? The first address is the network address (e.g. 192.168.1.0), and the last is the broadcast address (e.g. 192.168.1.255). Neither can be assigned to a host.

Quick Subnetting Method

Given 192.168.10.0/26, what are the network details?

  • Prefix: /26 → subnet mask 255.255.255.192
  • Block size: 256 − 192 = 64
  • Subnets: 192.168.10.0, 192.168.10.64, 192.168.10.128, 192.168.10.192
  • First subnet hosts: 192.168.10.1 – 192.168.10.62
  • Broadcast of first subnet: 192.168.10.63

Practice drill: Pick any /24 and practice carving it into /26s, /27s, and /28s until you can do it in under 60 seconds. This comes up on the exam repeatedly.

First Steps in Cisco CLI

If you've never touched IOS (Cisco's operating system), the CLI has a distinct mode hierarchy that trips people up at first. Here's the structure:

Exec Modes

  • User EXEC (Router>): Read-only. Can ping, trace, show limited info.
  • Privileged EXEC (Router#): Full show commands, debug. Enter with enable.
  • Global Config (Router(config)#): Make changes. Enter with configure terminal.
  • Interface Config (Router(config-if)#): Configure a specific interface. Enter with interface <type> <number>.

Essential Show Commands

! Check interface status and IP addresses
show ip interface brief

! View the full running configuration
show running-config

! Check routing table
show ip route

! View CDP neighbors (adjacent Cisco devices)
show cdp neighbors

! Check version and hardware info
show version

Basic Router Configuration Walkthrough

! Enter privileged exec mode
enable

! Enter global configuration mode
configure terminal

! Set hostname
hostname R1

! Configure an interface
interface GigabitEthernet0/0
  ip address 192.168.1.1 255.255.255.0
  no shutdown
  description LAN-Interface
  exit

! Save config to NVRAM
end
write memory
! or: copy running-config startup-config

Gotcha: By default, router interfaces are administratively shut down. You must explicitly run no shutdown to bring them up. Forgetting this is a classic lab mistake.

Useful CLI Shortcuts

  • ? at any point lists available commands or completions
  • Tab autocompletes a command if unambiguous
  • do show ... runs show commands from within config mode
  • no <command> negates / removes a configuration
  • Ctrl+Z exits to privileged EXEC from any config mode

Resources I'm Using

There's a lot of CCNA content out there. Here's what's actually worked for me in week 1:

  • Jeremy's IT Lab (YouTube / Udemy) — Free, methodical, and covers every exam topic. The best free resource hands down.
  • Cisco Packet Tracer — Free simulator from Cisco. Essential for practising CLI without real hardware. Download it from Cisco's NetAcad site (free account required).
  • Official Cert Guide (Wendell Odom) — Dense but authoritative. Good for looking things up rather than reading cover to cover.
  • SubnettingPractice.com — Drill subnetting questions until they're automatic.
  • Anki — I'm building a deck for OSI layers, port numbers, and protocol details. Spaced repetition beats re-reading notes every time.

Week 2 will cover switching fundamentals — VLANs, STP, and trunk links. Notes incoming.
